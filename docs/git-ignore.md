# ExtraTime — Git Ignore Guide & Documentation

This document explains the `.gitignore` configuration for the **ExtraTime** repository, detailing why specific files and directories are ignored, how secrets and build outputs are managed, and how to troubleshoot common Git tracking issues.

---

## 1. Overview & Purpose

A clean, predictable Git repository ensures that:
1. **Secrets & Credentials Never Leak:** API keys, database connection strings, and local environment variables stay securely on the developer's machine.
2. **Build Outputs & Caches Are Excluded:** Compiled assets (`.next/`, `build/`, `*.tsbuildinfo`) and dependency bundles (`node_modules/`) do not pollute git history.
3. **OS & Editor Differences Are Isolated:** Operating system metadata (`.DS_Store`, `Thumbs.db`) and IDE-specific configurations (`.vscode/`, `.idea/`) do not cause merge conflicts across team members.
4. **Repository Size Remains Lean:** Fast cloning, snappy indexing, and efficient CI/CD runs.

## 2. Ignored Categories & Rules Breakdown

### Dependencies & Package Managers
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `/node_modules` | Node.js / pnpm package dependencies (installed locally via `pnpm install`). Never committed. |
| `/.pnp`, `.pnp.*` | Yarn Plug'n'Play temporary files. |
| `.yarn/*` (with exceptions) | Yarn caches and runtime files, while preserving patches, plugins, and releases if Yarn berry is used. |

### Next.js & Build Artifacts
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `/.next/` | Next.js compilation cache, client/server bundles, and Turbopack output generated during development and build. |
| `/out/` | Static HTML export directory (`next export`). |
| `/build/` | Production build directory. |
| `next-env.d.ts` | Next.js auto-generated TypeScript declarations (regenerated automatically on dev/build). |
| `*.tsbuildinfo` | TypeScript incremental compilation cache file. |

### Convex Backend & Local Database State
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `.convex/` | Convex local development metadata, local storage emulator state, and environment links. |

### Environment Variables & Secrets (CRITICAL)
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `.env*` | All environment files (`.env`, `.env.local`, `.env.development.local`, `.env.production.local`, etc.). These contain sensitive tokens, API secrets, and Convex deployment keys. |

> [!CAUTION]
> **Never commit `.env` or `.env.local` files!**
> Always share required environment schemas via a sanitized `.env.example` template containing placeholder values.

### Logs & Diagnostics
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `*.log` | General application or process logs (e.g., `next-dev-current.out.log`, `next-dev-current.err.log`). |
| `npm-debug.log*` | NPM execution failure logs. |
| `yarn-debug.log*`, `yarn-error.log*` | Yarn failure logs. |
| `.pnpm-debug.log*` | PNPM debug logs. |
| `scratch/` | Temporary local scratchpad scripts or experiments. |

### Operating System Metadata
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `.DS_Store` | macOS Finder folder view settings and desktop metadata. |
| `Thumbs.db`, `ehthumbs.db` | Windows Explorer thumbnail preview caches. |
| `[Dd]esktop.ini` | Windows custom folder layout settings. |

### IDE & Editor Workspaces
| Pattern | Purpose / Rationale |
| :--- | :--- |
| `.vscode/` | Visual Studio Code project-specific settings, tasks, and debug profiles (unless team-shared). |
| `.idea/` | JetBrains IDE workspace files. |
| `*.swp`, `*.swo` | Vim swap and backup files. |
| `.vercel` | Vercel CLI project linkage and deployment artifacts. |
| `/coverage` | Test coverage reports generated by test runners (Jest, Vitest). |

## 3. Best Practices & Team Guidelines

### 1. Handling Environment Variables Safely
When introducing a new environment variable:
1. Add the variable to your local `.env.local`:
   ```bash
   NEXT_PUBLIC_CONVEX_URL="https://your-deployment.convex.cloud"
   CONVEX_DEPLOY_KEY="prod:your-secret-key"
   ```
2. Add the variable with an empty/dummy placeholder to `.env.example`:
   ```bash
   NEXT_PUBLIC_CONVEX_URL="https://example.convex.cloud"
   CONVEX_DEPLOY_KEY=""
   ```
3. Commit `.env.example` so teammates and CI/CD pipelines know the required configuration keys.

### 2. Testing if a File is Ignored
To check whether Git is currently ignoring a file and view the exact rule responsible:
```bash
git check-ignore -v <path/to/file>
```
*Example:*
```bash
git check-ignore -v .env.local
# Output: .gitignore:36:.env*    .env.local
```

### 3. Untracking Files Accidentally Committed
If a file was tracked before adding it to `.gitignore`:
```bash
# Untrack a single file (keeps it on your local disk):
git rm --cached <path/to/file>

# Untrack an entire folder (e.g., .next or node_modules):
git rm -r --cached <folder-path>

# Commit the removal:
git commit -m "chore: stop tracking ignored files"
```

### 4. Refreshing Git Index After Changing `.gitignore`
If you made significant changes to `.gitignore` and need to apply them to all untracked files:
```bash
# 1. Stage everything for re-indexing
git rm -r --cached .

# 2. Re-add everything according to the new .gitignore
git add .

# 3. Commit the cleaned index
git commit -m "chore(git): re-index repository with updated .gitignore"
```

### 5. Personal / Local Overrides (`.git/info/exclude`)
If you want to ignore files on your local machine only without affecting other developers:
- Edit `.git/info/exclude` in your repository.
- Patterns in this file act just like `.gitignore`, but are private to your local clone.
